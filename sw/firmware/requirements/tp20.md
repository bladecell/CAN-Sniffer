# TP 2.0 Transport Component — Requirements

Component to create: `components/tp20` (ESP-IDF C++, follows the conventions of `components/obd2` and
`components/can_driver`: singleton classes, `init()/deinit()` lifecycle, FreeRTOS tasks pinned to
`CORE_ID_CAN_TASKS`, compiled with `-Wall -Wextra -Werror`).

Purpose: VW Transport Protocol 2.0 (TP 2.0) channel transport over the existing CAN driver, used by
VW PQ35 modules (Golf VI) that do not answer UDS/ISO-TP. Protocol reference: https://jazdw.net/tp20
(community-documented; treat deviations discovered on real hardware as findings, log them, do not
silently "fix" the spec).

The words MUST / SHOULD / MAY follow RFC 2119. Every FR has a matching test requirement (TR).

---

## 1. Dependencies (existing code — do not modify)

| API | Use |
|---|---|
| `CanDriver::transmit(CanFrame&, timeout_ms)` | normal TX |
| `CanDriver::transmitUrgent(CanFrame&)` | ACKs, channel-setup (re)tries, keep-alive — these must preempt any bulk traffic |
| `CanDriver::receive(CanFrame&, timeout_ms)` | single RX pump owned by this component |
| `CanDriver::isBusConnected()` / connection-change callback | gate the state machine; bus loss => all channels DEAD |
| `CanDriver::CanFrame` (`header`, `data[8]`, `length`, `ts_us`) | frame type (classic CAN, 11-bit IDs only) |

This component MUST NOT touch `components/obd2` (arbitration is owned by the caller, see vag_diag
requirements). It MUST NOT configure bitrate, filters, or pins — `can_driver.init()` is the caller's job.

## 2. Protocol reference (byte-exact)

All frames are classic CAN, 11-bit IDs, 500 kbit/s (set by caller).

### 2.1 Channel setup (fixed 7 data bytes)
```
request : CAN ID 0x200            [dest][0xC0][RX_ID][V|RXPref][TX_ID][V|TXPref][app]
response: CAN ID 0x200 + dest     [dest][0xD0][RX_ID][V|RXPref][TX_ID][V|TXPref][app]  (positive)
                                   [dest][0xD6..0xD8]...                                (negative)
```
- `dest` = VAG logical module address (e.g. 0x01 engine, 0x19 gateway).
- "Pref" byte = ID prefix (high nibble) + validity flag (0x1 = invalid/ignore ID).
- Request default: RX_ID=0x00 V=1 (invalid, we accept anything), TX_ID=0x00–0x10 requested as 0x300+n,
  `app=0x01`. The ECU's response dictates the real IDs (commonly the ECU transmits on **0x740**).
- After a positive response both sides switch to the negotiated IDs:
  - tester -> ECU on the RX_ID the ECU accepted (when its V flag is 0), else on the ID we asked for;
  - ECU -> tester on TX_ID from its response.

### 2.2 Channel parameters (6 data bytes; 1-byte variants for A3/A4/A8)
```
[op][BS][T1][T2][T3][T4]
  0xA0 params request   (ECU -> tester after setup)
  0xA1 params response  (tester -> ECU; also the reply format for 0xA0)
  0xA3 channel test     (1 byte; reply = 0xA1 6-byte params frame)  -- keep-alive
  0xA4 break            (1 byte; receiver discards un-ACKed data)
  0xA8 disconnect       (1 byte; receiver replies with 0xA8)
timing byte encoding: bits[7:6] units (0=0.1ms, 1=1ms, 2=10ms, 3=100ms), bits[5:0] scale.
Known-good default from a Golf V engine capture: `A0 0F 8A FF 32 FF` decoded:
  BS = 0x0F              -> 15 packets per block before an ACK is required
  T1 = 0x8A              -> units 0b10 (10 ms) x scale 10  = 100 ms  (ACK wait; must satisfy T1 > 4*T3)
  T2 = 0xFF              -> unused
  T3 = 0x32              -> units 0b00 (0.1 ms) x scale 50 = 5 ms   (inter-packet gap on TX)
  T4 = 0xFF              -> unused
MUST be configurable per call; the implementer MUST decode/encode via a helper (no raw bit math at
call sites) so units are never confused.
```

### 2.3 Data transmission (2..8 data bytes)
```
[op][seq][payload...]
  op 0x0 waiting for ACK, more packets follow
  op 0x1 waiting for ACK, last packet
  op 0x2 no ACK required, more packets follow
  op 0x3 no ACK required, last packet
  op 0xB ACK, ready for next packet      (byte1 = seq being ACKed, e.g. B1, B5)
  op 0x9 ACK, not ready                  (flow control)
seq: 4-bit sequence number in bits[3:0] of byte 1, increments per packet, wraps 0xF -> 0x0.
```
- A TP 2.0 *message* (a KWP2000 request/response) is fragmented across packets. The first 2 payload
  bytes of a message carry its 16-bit **big-endian** total length; remaining bytes are message data.
- On **responses**, the high nibble of the second byte of the first frame carries flags; `0x80` in that
  nibble means NRC 0x78 (responsePending) — length is then 12 bits (low nibble of byte1 + byte0).
  Implement per the jazdw note; verify on hardware.

### 2.4 Broadcast (fixed 7 data bytes) — MAY be implemented last (FR-9)
```
[dest][0x23 | 0x24][kwp data (4 bytes)][resp-req][resp-req]
  0x23 broadcast request, 0x24 response; resp-req 0x00 = response expected, 0x55/0xAA = none.
```

## 3. Functional requirements

- **FR-1 Frame codec**: pure, allocation-free functions `tp20::codec` that parse/serialize every frame
  type in §2 from/to `(can_id, data[8], len)`. Parse failures return a typed error, never throw.
- **FR-2 Channel open**: `openChannel(addr, timeout_ms)` performs: setup request on 0x200 (2 retries,
  250 ms response window each) -> positive response on 0x200+addr -> send params 0xA1 -> wait 0xA0
  from ECU -> reply 0xA1. Returns the negotiated (rx_id, tx_id) to the caller.
- **FR-3 RX demux**: one task receives from `can_driver` and routes frames by CAN ID to the matching
  open channel or to the setup listener (0x200+addr). Frames for no channel are dropped (counted).
- **FR-4 Data send**: `sendData(payload, len)` fragments a message (16-bit BE length prefix +
  payload) into packets honoring the negotiated BS: after BS packets with op 0x0, wait for ACK
  (op 0xB) up to T1; ACK op 0x9 = wait and re-probe. Seq tracking per channel, wrap at 0xF.
  Packets MUST be paced by T3 (the negotiated inter-packet gap, default 5 ms with the §2.2 params):
  gap measured from the TX-done of the previous packet, not from queueing.
- **FR-4b Seq integrity**: on a received data packet whose seq does not continue the expected count,
  discard the partial reassembly, increment a seq-error counter, send 0xA4 (break) and wait for the
  sender to restart the message. Never surface a partially reassembled message to the caller.
- **FR-5 Data receive**: `recvData(buf, len, timeout_ms)` reassembles a complete message (all packets
  through op 0x1/0x3) and handles the responsePending flag (§2.3) by continuing to listen. Sends
  ACK (0xB+seq) for every frame received with op 0x0/0x1, before returning the message.
  Assembly timeout policy (values observed in VCDS.exe's assembler, `FUN_00470024` — the envelope a
  real tester tolerates; adopt as defaults):
  | Condition | Next-packet wait |
  |---|---|
  | normal | 250 ms |
  | address 0x46 (special-cased in VCDS) | 750 ms |
  | address 0x31 (special-case) | 1500 ms |
  | nothing received yet, post-request grace | 4000 ms |
  Overall aborts: **5 s** since the request when the request was `0x1A` (ident), else **7 s**;
  **30 s** when the last received packet is `7F 78` (NRC responsePending). Hard caps: 256 packets per
  message and 1500 receive-loop iterations, after which the assembly fails with a typed error.
- **FR-6 Keep-alive**: per open channel, send 0xA3 every `keepalive_ms` (default 2000) while idle;
  2 missed replies (0xA1) => channel DEAD, callback fires.
- **FR-7 Disconnect**: `closeChannel()` sends 0xA8 and waits for the 0xA8 echo (200 ms); state DEAD
  either way. `deinit()` MUST close all open channels best-effort.
- **FR-8 Multi-channel**: support up to 3 concurrently open channels (distinct negotiated IDs).
  Registry lookups are O(1)-ish and lock-free on the RX path (listener IDs are published atomically).
- **FR-9 Broadcast**: `broadcast(dest, kwpData, respReq)` per §2.4, sent 5x back-to-back.
- **FR-10 Error surface**: every timeout/negative response/bus-off is observable: per-channel status
  enum (`IDLE, OPENING, OPEN, DEAD`) + last-error code + a counters struct (frames rx/tx, drops,
  timeouts). No printf-style logging in the RX hot path (ESP_LOGx only on state changes, IDED).
- **FR-11 Lifecycle**: `init(const Config&)` starts the RX task (priority = TX_TASK_PRIO-1, core
  `CORE_ID_CAN_TASKS`); `deinit()` closes channels, drains, deletes the task. Both idempotent and
  safe against concurrent calls, matching `CanDriver::deinit()` semantics.

### 3.1 Timing profile constants (implement as `tp20_timing.hpp`, one `#define` per value)

House style mirrors `obd2_common.hpp`. **These are NOT interchangeable with the OBD-II ISO-TP
profile** (`ISOTP_N_*`, `OBD2_*`): TP 2.0 is a different transport — ACKs are per BS-block
(negotiated), packet pacing is negotiated (T3), channels are unicast (no functional-broadcast
quiet gap), and the KWP pending wait is longer. Do not reuse or fall back to the OBD2 values.

```c
// TP 2.0 / KWP timing profile. T1/T3/BS below are the DEFAULTS matching the profile VCDS
// negotiates (A0 0F 8A FF 32 FF); the live values come from the 0xA0/A1 exchange and MUST
// override these once a channel is open. N_* ISO-TP timers do not exist on this transport:
// the receiver ACKs per block (BS, T1) instead of a single flow-control frame (N_Ar).
#define TP20_T1_ACK_WAIT_MS 100             // negotiated T1 (from 0x8A): wait for the 0xB ACK after a full BS block
#define TP20_T3_PACKET_GAP_MS 5             // negotiated T3 (from 0x32): TX pacing, measured TX-done to next TX
#define TP20_BS_BLOCK_SIZE 15               // negotiated BS (from 0x0F): data packets per ACK block
#define TP20_NEXT_PACKET_WAIT_MS 250        // receiver: wait for the next packet of an open message (VCDS assembler default)
#define TP20_FIRST_PACKET_GRACE_MS 4000     // receiver: post-request grace while nothing has arrived yet
#define TP20_SPECIAL_ADDR_46_WAIT_MS 750    // VCDS special-cases address 0x46 with a longer packet wait
#define TP20_SPECIAL_ADDR_31_WAIT_MS 1500   // VCDS special-cases address 0x31 likewise
#define TP20_ABORT_SINCE_REQ_IDENT_MS 5000  // overall assembly abort when the request was KWP 0x1A (ident)
#define TP20_ABORT_SINCE_REQ_MS 7000        // overall assembly abort otherwise
#define TP20_PENDING_TOTAL_WAIT_MS 30000    // last packet was KWP NRC 0x78 (7F 78): keep waiting this long in total
#define TP20_MAX_PACKETS_PER_MESSAGE 256    // runaway guard (VCDS aborts with its 0xFFFFF6 error past this)
#define TP20_MAX_RX_LOOP_ITERATIONS 1500    // runaway guard (VCDS aborts with 0xFFFFFF9C past this)
```

Receiver policy notes (same philosophy as the OBD2 block): the next-packet wait is restarted per
valid in-sequence packet (like N_Cr); the since-request aborts are tester policy taken from
VCDS's assembler, not standard values; T1/T3/BS always come from the channel negotiation once
open — the `#define`s are only the values we REQUEST during setup and the fallbacks if a peer
accepts our proposal verbatim.

## 4. Public API (header sketch — implement exactly these)

```cpp
namespace tp20 {
struct Config {
    uint32_t default_timeout_ms = 250;
    uint8_t  max_setup_retries  = 2;
    uint32_t keepalive_ms       = 2000;
    uint8_t  max_channels       = 3;
};
struct ChannelIds { uint32_t rx_id; uint32_t tx_id; };   // negotiated
enum class ChState : uint8_t { IDLE, OPENING, OPEN, DEAD };

class Tp20 {
public:
    static Tp20& getInstance();
    esp_err_t init(const Config& cfg);      // requires an initialized CanDriver
    esp_err_t deinit();

    esp_err_t openChannel(uint8_t vag_addr, ChannelIds& out, uint32_t timeout_ms);
    esp_err_t sendData(uint8_t vag_addr, const uint8_t* msg, size_t len, uint32_t timeout_ms);
    esp_err_t recvData(uint8_t vag_addr, uint8_t* buf, size_t buf_size,
                       size_t& msg_len, uint32_t timeout_ms);   // complete reassembled message
    esp_err_t closeChannel(uint8_t vag_addr, uint32_t timeout_ms);
    ChState state(uint8_t vag_addr) const;

    esp_err_t broadcast(uint8_t dest, const uint8_t* kwp_data, size_t len, bool response_expected);
};
} // namespace tp20
```
`vag_addr` is the key for all channel calls. `recvData` is single-consumer per channel
(return ESP_ERR_INVALID_STATE on concurrent recv).

## 5. Non-functional requirements

- NRF-1 No heap allocation after `init()` on TX/RX paths (static buffers; one message buffer per
  channel, sized 4096 bytes).
- NRF-2 All timeouts bounded; no busy-wait; ISR context only via `can_driver` hooks (FrameTap NOT
  required by this component).
- NRF-3 Codec + state machine unit-testable on the host (no ESP-IDF includes in `tp20_frames`).
- NRF-4 Log tag `tp20`; state transitions at INFO, drops at DEBUG (counter only), errors at ERROR.

## 6. Test requirements

- **TR-1 Host unit tests** (`test/` native or pytest-driven, house pattern) for the codec: parse+serialize
  round-trips for every frame type; invalid opcode / wrong length / bad V-flag handling.
- **TR-2 Transcript fixture test**: replay the full jazdw.net worked example (engine measuring block
  session: 200 setup, 201 response, 740/300 params, data + ACKs, A8 disconnect) through the codec and
  a scripted channel machine; assert byte-exact outputs and the reassembled KWP message
  `61 01 01 00 00 ...` (26 bytes).
- **TR-3 Loopback test on target** (googletest component test, gated on hardware): use the existing
  `obd2_simulator` pattern — a fake ECU task that answers setup/params/data per the transcript; assert
  `openChannel`/`sendData`/`recvData`/`closeChannel` succeed end-to-end over TWAI loopback.
- **TR-4 Timing tests**: ACK timeout (T1), setup retry count, keep-alive miss => DEAD transition,
  T3 pacing (assert packet-to-TX-done gaps >= T3), seq-error path (0xA4 break sent, no partial
  message surfaced), and **negotiated-parameter override**: after a scripted 0xA0/A1 exchange with
  non-default T1/T3/BS, the channel uses the negotiated values, not the `#define` defaults.

## 7. Acceptance criteria

1. TR-1 and TR-2 pass on host; TR-3 passes on target with a scripted fake ECU.
2. Channel to a real Golf VI engine (0x01) opens from the bench: positive 0xD0 on 0x201, negotiated
   IDs returned, keep-alive stable for >= 60 s without DEAD.
3. `deinit()` while a channel is open closes cleanly (no leaked tasks/queues; assert via existing
   lifecycle test access pattern of can_driver).
4. `-Werror` clean; no new warnings; host tests run in CI script alongside existing suite.
